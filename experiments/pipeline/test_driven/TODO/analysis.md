# Analysis Report: Adding `due_date` Field to Task Model

## Task Objective
Add an optional `due_date: Optional[datetime]` field to the Task dataclass with CEST (UTC+2) timezone awareness, ISO 8601 storage format, and full serialization support while maintaining backward compatibility with existing stored data.

---

## Current Task Model Structure

**File:** `src/models/task.py`

**Dataclass attributes:**
1. `title: str` — required field (positional)
2. `id: str` — auto-generated UUID (default factory)
3. `description: Optional[str]` — nullable (default None)
4. `status: TaskStatus` — enum value (default TaskStatus.PENDING)
5. `created_at: datetime` — UTC timezone-aware (default factory creates datetime.now(timezone.utc))
6. `updated_at: datetime` — UTC timezone-aware (default factory creates datetime.now(timezone.utc))

**Key methods:**
- `__init__()` — auto-generated by @dataclass decorator
- `to_dict() -> dict` — serializes all fields; status converted to string via `.value`; both timestamps to ISO format via `.isoformat()`
- `from_dict(data: dict) -> Task` — class method that deserializes dict to Task; uses `.get()` for optional fields; uses `TaskStatus()` enum constructor and `datetime.fromisoformat()` for parsing

**Current dataclass decorator:** `@dataclass` (no parameters)

## What Needs to Be Modified

### Files to modify:
1. **`src/models/task.py`** — the Task model itself

### Specific changes in Task model:

**In `__init__` parameter list (dataclass field):**
- Add `due_date: Optional[datetime] = None` as a new field after `status` or at the end of field definitions
- Field must support None as default

**In `to_dict()` method:**
- Add handling for `due_date`: if it exists and is not None, serialize to ISO format string via `.isoformat()`
- If `due_date` is None, include it in the dict as None or omit it (test expects `"due_date" in d` to be true)

**In `from_dict()` class method:**
- Extract `due_date` using `.get("due_date")` to handle missing key (backward compatibility)
- If `due_date` is present in dict and not None, parse it via `datetime.fromisoformat()` and validate timezone
- Must reject naive datetimes (those without tzinfo)
- Must reject datetimes with timezones other than CEST (UTC+2)
- Pass parsed `due_date` to the Task constructor

**Validation requirements:**
- Invalid types (e.g., string "not-a-datetime") must raise an Exception when passed to `__init__`
- Naive datetimes (no tzinfo) must be rejected during deserialization
- Non-CEST timezones must be rejected during deserialization
- None values must be allowed and preserved
- Round-trip through `to_dict()` → `from_dict()` must preserve the exact datetime value

## Constraints and Edge Cases to Handle

1. **Timezone handling:**
   - CEST is UTC+2 (fixed offset, no DST); defined as `timezone(timedelta(hours=2))`
   - All due_dates must be timezone-aware (naive datetimes rejected)
   - All due_dates must use CEST specifically; other timezones rejected
   - `created_at` and `updated_at` already use UTC; `due_date` uses CEST

2. **Backward compatibility:**
   - Existing JSON files may lack the `due_date` key entirely
   - `from_dict()` must handle missing key gracefully
   - Old data must load with `due_date=None`

3. **Serialization format:**
   - Must store as ISO 8601 string in JSON (via `.isoformat()`)
   - Example: `"2026-06-01T12:00:00+02:00"` (with CEST offset)

4. **Validation:**
   - Invalid type passed to `Task(due_date=...)` must raise Exception
   - Naive datetime must raise Exception
   - Non-CEST timezone must raise Exception
   - None is valid (default state)

5. **to_dict() behavior:**
   - Test expects `"due_date" in d` to be true even when present with None value

6. **No changes needed to:**
   - `TaskManager` — handles via Task methods
   - `TodoService` — doesn't manipulate Task fields directly
   - `TodoCLI` — doesn't display due_date yet
   - `JsonStorage` — generic JSON serialization
